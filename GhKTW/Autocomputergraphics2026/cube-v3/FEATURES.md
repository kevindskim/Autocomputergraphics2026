# cube-v3: 최소 블렌더 뷰포트

cube-v2의 큐브 뷰어를 블렌더의 3D 뷰포트처럼 확장한 실습 코드입니다. 렌더링 모드, 궤도 카메라, 격자 바닥, 축 위젯, 물체 선택과 이동/회전 핸들을 다룹니다.

## cube-v2에서 달라진 점

| 항목 | cube-v2 | cube-v3 |
| --- | --- | --- |
| 창 구조 | `MainWidget` 하나 | `MainWindow` + 메뉴, 툴바, 상태바, 사이드 패널 |
| 화면 표현 | 텍스처만 | Wireframe, Solid, Textured |
| 배경과 바닥 | 검은 배경 | 회색 배경, 격자 바닥 |
| 드래그 | 트랙볼 방식으로 물체 회전 | 턴테이블 방식으로 카메라 공전 |
| 카메라 | 고정 | 공전, 시점 이동, 줌, 축 시점 전환 |
| 물체 조작 | 회전만 | 선택 후 축/평면 이동, 축별 회전 |
| 정점 데이터 | 위치, 텍스처 좌표 | 위치, 텍스처 좌표, 법선 |
| 근평면/원평면 | 3.0 / 7.0 | 0.1 / 1000 |

## 전체 동작 흐름

모든 기능이 같은 구조로 동작합니다. 입력은 상태 값만 바꾸고 `update()`로 다시 그리기를 요청하며, 실제 그리기는 `paintGL()`이 현재 상태로 합니다.

```
마우스/키 입력 → 상태 변경 (카메라 값, 물체 위치/방향, 선택, 모드) → update() → paintGL()
```

### 마우스 입력의 분기

좌클릭은 다음 순서로 처리됩니다.

| 순서 | 조건 | 결과 |
| --- | --- | --- |
| 1 | Shift를 누른 채 드래그 | 시점 이동 |
| 2 | 선택 상태에서 핸들 위를 누름 | 그 핸들로 물체 이동 또는 회전 |
| 3 | 그 외의 드래그 | 턴테이블 회전 |
| 4 | 움직이지 않고 뗌 | 광선 판정으로 선택 또는 해제 |

버튼을 누르지 않고 움직이면 핸들 호버 표시만 갱신합니다. 휠은 언제나 줌입니다.

### 한 프레임의 그리기 순서

1. 색 버퍼와 깊이 버퍼를 지웁니다.
2. 렌더링 모드에 맞게 `glPolygonMode`와 후면 제거를 설정합니다.
3. 큐브를 그립니다. 깊이 테스트가 켜져 있습니다.
4. 격자를 그립니다. 깊이 테스트로 큐브에 올바르게 가려집니다.
5. 선택되어 있으면 깊이 테스트를 끄고 핸들을 그립니다.

### 좌표 변환

| 방향 | 사용하는 곳 |
| --- | --- |
| 물체 → 월드 → 뷰 → 화면 (MVP) | 큐브 그리기, 핸들의 클릭 판정 (`project()`) |
| 화면 → 월드 (마우스 광선) | 선택, 이동, 회전 드래그 |
| 월드 → 물체 (모델 행렬의 역행렬) | 선택의 슬랩 테스트 |
| 월드 → 카메라 축 (내적) | 축 위젯 |

## 기능 1: 렌더링 모드 전환

| 모드 | 면 채우기 | 후면 제거 | 프래그먼트 색 |
| --- | --- | --- | --- |
| Wireframe | `GL_LINE` | 끔 | 고정된 밝은 회색 |
| Solid | `GL_FILL` | 켬 | 회색 재질 + Lambert 음영 |
| Textured | `GL_FILL` | 켬 | 텍스처 색 |

두 단계에서 모드가 갈립니다.

- **래스터화 단계**: `paintGL()`에서 `glPolygonMode`와 `GL_CULL_FACE`를 바꿉니다.
- **프래그먼트 단계**: `render_mode` uniform 값에 따라 셰이더의 분기가 달라집니다.

`RenderMode` 열거형의 값은 `fshader.glsl`의 상수와 일치해야 합니다.

### Solid 모드의 음영

음영 계산에는 법선이 필요해서 정점 데이터에 `normal`을 추가했습니다. 큐브는 면마다 정점을 따로 가지므로 면별 법선을 그대로 넣을 수 있습니다.

```
색 = 기본색 * (ambient + (1 - ambient) * max(N·L, 0))
```

- `N`은 뷰 좌표계의 법선입니다. 법선 행렬(모델뷰 3×3의 역전치)로 변환합니다.
- `L`은 뷰 좌표계에 고정된 빛 방향입니다. 그래서 회전하면 면의 밝기가 바뀌고, 시점을 평행이동해도 밝기는 그대로입니다.

## 기능 2: 카메라 상태

v3의 카메라는 네 가지 값으로 정해집니다. `cameraPosition`, `cameraRight`, `cameraUp`은 직접 바꾸지 않고 `updateCameraPosition()`에서 항상 이 값들로 계산합니다.

| 값 | 의미 | 바꾸는 입력 |
| --- | --- | --- |
| `cameraTarget` | 회전 기준점 (항상 화면 중앙) | Shift + 드래그 |
| `cameraYaw` | 좌우 각도 | 드래그 |
| `cameraPitch` | 상하 각도 (±90°로 제한) | 드래그 |
| `cameraDistance` | 기준점까지의 거리 (2~50) | 휠 |

눈의 위치는 기준점을 중심으로 한 구면좌표입니다.

```
direction = (sin(yaw) * cos(pitch), sin(pitch), cos(yaw) * cos(pitch))
cameraPosition = cameraTarget + direction * cameraDistance
```

카메라의 up 벡터도 같은 각도에서 계산합니다. 월드 y축을 up으로 고정하면 바로 위에서 볼 때 시선과 평행해져 `lookAt`을 계산할 수 없습니다.

```
right = (cos(yaw), 0, -sin(yaw))
up    = (-sin(yaw) * sin(pitch), cos(pitch), -cos(yaw) * sin(pitch))
```

이 두 벡터는 `direction`을 yaw와 pitch로 미분한 방향이라서 시선과 항상 수직입니다. 그래서 pitch가 정확히 ±90°여도 문제가 없습니다.

## 기능 3: 시점 이동 (Shift + 드래그)

`cameraTarget`을 옮기면 눈도 같은 양만큼 따라갑니다. 시선 방향이 그대로이므로 보는 각도는 바뀌지 않고, 회전 기준점이 함께 옮겨집니다.

1. **픽셀당 월드 거리**를 구합니다. 카메라에서 거리 `d`인 평면의 화면 높이는 `2 * d * tan(fov / 2)`이고, 이를 뷰포트 높이로 나눕니다.
2. **카메라 축**은 `updateCameraPosition()`이 계산해 둔 `cameraRight`와 `cameraUp`을 씁니다.
3. **마우스 반대 방향**으로 카메라를 옮깁니다. 그래야 장면이 마우스를 따라옵니다. 화면 y는 아래로 증가하므로 부호에 주의합니다.

```
offset = (up * diff.y - right * diff.x) * worldPerPixel
```

기준점을 지나는 평면이 마우스를 정확히 따라옵니다. 처음 상태에서 앞면은 카메라에서 거리 4, 기준점은 거리 5이므로 앞면은 마우스보다 5/4배 빠르게 움직입니다. 원근 투영에서는 정상적인 현상입니다. 이동량이 거리에 비례하므로 줌을 해도 같은 평면이 마우스를 따라옵니다.

## 기능 4: 턴테이블 회전 (드래그)

v2까지는 물체를 트랙볼 방식으로 돌렸습니다. 회전이 누적되어 화면이 옆으로 기우는 롤(roll)이 생기고, 회전 중심이 물체에 고정되어 시점을 옮겨도 따라오지 않았습니다. v3에서는 드래그가 물체 대신 카메라를 움직여, 카메라가 기준점 주위를 공전합니다. 물체를 직접 돌리는 것은 회전 호가 맡습니다.

- **좌우 드래그**: 월드 y축을 중심으로 회전합니다. (`cameraYaw`)
- **상하 드래그**: 카메라 x축을 중심으로 회전합니다. (`cameraPitch`)

상하 회전축은 월드 축이 아니라 카메라와 함께 도는 축입니다. 시선 축을 중심으로 한 회전은 입력에 없으므로 수평선이 기울지 않습니다.

`mouseMoveEvent()`는 이벤트마다 Shift 상태를 확인하므로, 드래그 중에 Shift를 누르거나 떼도 회전과 이동이 끊김 없이 바뀝니다.

## 기능 5: 휠 줌

카메라가 시선 방향으로 기준점에 다가가는 돌리(dolly) 방식입니다. FOV는 바꾸지 않습니다. 휠 한 칸마다 거리에 0.9를 곱하므로, 거리와 상관없이 한 칸의 체감이 같습니다.

`cameraDistance`가 범위를 벗어나지 않도록 2~50으로 제한합니다. 근평면/원평면은 3.0/7.0에서 0.1/1000으로 넓혔습니다. 이전 값으로는 줌을 하면 큐브가 잘립니다.

## 기능 6: 회색 배경과 격자 바닥

- **배경**: `glClearColor`를 0.23 회색으로 바꿨습니다.
- **격자**: 월드 xz 평면에 1 간격, ±20 범위로 선을 그립니다. 큐브 바닥과 겹치면 깊이 버퍼에서 z-fighting이 생기므로 y = -1.01에 둡니다.
- **좌표축 선**: 원점을 지나는 선은 색을 다르게 합니다. X축 방향은 빨강, Z축 방향은 파랑입니다.
- **별도 셰이더와 VAO**: 격자는 텍스처와 법선이 없고 정점 형식이 달라서 `gridvshader.glsl`, `gridfshader.glsl`을 따로 씁니다. 정점이 이미 월드 좌표이므로 MVP에서 모델 행렬이 빠집니다.
- **멀티샘플링**: 얇은 선의 계단 현상을 줄이려고 `QSurfaceFormat::setSamples(4)`를 켰습니다.

## 기능 7: 사이드 패널과 축 위젯

`QDockWidget`으로 만든 패널에 `AxisGizmo` 위젯이 들어 있습니다. 도킹 위치를 옮기거나 떼어 낼 수 있고, `toggleViewAction()`이 제공하는 액션을 툴바와 메뉴에 그대로 넣어 열고 닫습니다.

### 축 그리기

`AxisGizmo`는 OpenGL이 아니라 `QPainter`로 그리는 커스텀 위젯입니다. 월드 축을 카메라 축에 내적하면 화면 위치가 나옵니다. 원근 없이 회전만 반영하는 직교 투영입니다.

```
화면 x = dot(축, cameraRight)
화면 y = -dot(축, cameraUp)     // 위젯 y는 아래로 증가
깊이   = dot(축, cross(cameraRight, cameraUp))     // 양수면 카메라 쪽
```

깊이 순으로 정렬해 먼 것부터 그립니다(화가 알고리즘). 클릭 판정은 반대로 가까운 것부터 확인하므로, 겹쳐 있으면 위에 보이는 원이 선택됩니다.

### 시점 전환

`updateCameraPosition()`이 보내는 `cameraChanged` 시그널로 위젯이 카메라를 따라갑니다. 축을 클릭하면 `axisClicked` 시그널이 `MainWidget::viewAlongAxis()`로 전달되고, 방향을 구면좌표로 역변환해 각도를 정합니다.

```
yaw   = atan2(direction.x, direction.z)
pitch = asin(direction.y)
```

`cameraTarget`과 `cameraDistance`는 그대로이므로 기준점과 줌은 유지됩니다.

정면으로 보는 축의 반대쪽 끝은 앞쪽 원에 가려 클릭할 수 없습니다. 그래서 이미 정면인 축을 다시 클릭하면 반대쪽으로 넘어갑니다. 블렌더와 같은 방식입니다.

## 기능 8: 물체 선택

마우스 위치를 월드 공간의 광선으로 바꾸고, 그 광선이 큐브에 맞는지 계산합니다.

1. **마우스 광선**: 투영의 역과정입니다. 픽셀을 NDC(-1~1)로 바꾼 뒤 카메라 축으로 방향을 만듭니다.

   ```
   방향 = forward + right * ndcX * tan(fov / 2) * aspect + up * ndcY * tan(fov / 2)
   ```

2. **물체 좌표계로 변환**: 모델 행렬의 역행렬로 광선을 옮깁니다. 물체 좌표계에서 큐브는 축에 정렬된 상자이므로, 회전한 큐브도 같은 계산으로 처리됩니다.
3. **슬랩 테스트**: 세 쌍의 평행한 평면마다 광선이 들어오고 나가는 t를 구합니다. 가장 늦은 진입이 가장 이른 이탈보다 앞서면 상자를 지나간 것입니다.

클릭과 드래그는 눌렀다 뗄 때까지 3픽셀 넘게 움직였는지로 구분합니다. 큐브 위에서 드래그하면 선택되지 않고 카메라가 회전합니다.

## 기능 9: 이동 핸들

`TransformGizmo`는 수학만 담당하고, 그리기는 `GeometryEngine`이 합니다.

- **그리기**: 깊이 테스트를 끄고 맨 마지막에 그려서 큐브에 가려지지 않습니다.
- **크기**: 길이를 픽셀로 정한 뒤 물체 깊이의 픽셀당 월드 거리를 곱합니다. 그래서 줌을 해도 화면에서 크기가 같습니다.
- **두꺼운 선**: Core 프로파일에서는 `glLineWidth`를 믿을 수 없어서, 카메라를 향하는 얇은 삼각형 띠로 그립니다. 띠의 방향은 `cross(선 방향, 카메라 방향)`입니다.
- **클릭 판정**: 3D 점을 화면으로 투영해 2D에서 판단합니다. 축과 호는 선분까지의 거리, 직각 표시는 사각형 내부 여부를 봅니다.
- **숨김**: 카메라를 똑바로 향하는 축은 점으로 보여서 숨기고, 옆면으로 보이는 평면 표시도 숨깁니다.

### 축 방향 이동

마우스 광선과 축 직선의 **최근접점**을 구합니다. 두 직선은 보통 만나지 않으므로, 가장 가까운 점의 축 위 위치 `s`를 씁니다. `a`는 축 방향, `d`는 광선 방향(둘 다 단위 벡터), `w`는 축 위의 점에서 광선 시작점을 뺀 벡터입니다.

```
b = dot(a, d)
s = (b * dot(d, w) - dot(a, w)) / (1 - b²)
새 위치 = 시작 위치 + a * (s - 시작할 때의 s)
```

`1 - b²`이 0에 가까우면 광선과 축이 평행하다는 뜻이므로 그 입력은 무시합니다. 원근까지 포함해 계산하므로 잡은 점이 커서를 따라옵니다. 축과 다른 방향으로 끌어도 물체는 축 위에서만 움직입니다.

### 평면 위 이동

축 사이의 직각 표시를 끌면 **광선과 평면의 교점**을 따라갑니다. 평면은 물체를 지나고 법선이 나머지 한 축입니다.

```
t = dot(평면 위의 점 - 광선 시작, n) / dot(광선 방향, n)
새 위치 = 시작 위치 + (현재 교점 - 시작 교점)
```

색은 블렌더처럼 법선 축의 색을 씁니다. XY 평면 표시는 Z축 색인 파랑입니다.

## 기능 10: 회전 호

`R`을 누르면 축이 호로 바뀝니다. 호는 각 축을 법선으로 하는 원에서 카메라 쪽 부분만 그린 것입니다. 옆면으로 보면 반원이고, 원을 정면으로 볼수록 길어져 완전히 마주보면 원이 됩니다.

회전은 월드 축 기준이라서 새 회전을 앞에 곱합니다.

```
새 방향 = R(월드 축, 각도) * 시작 방향
```

각도는 호가 보이는 정도에 따라 두 방식으로 구합니다.

- **호가 열려 있을 때** (`|dot(축, 카메라 방향)| >= 0.3`): 호의 평면과 광선의 교점을 구하고, 시작 교점과 현재 교점 사이의 각도를 계산합니다. 잡은 점이 커서를 따라옵니다.

  ```
  각도 = atan2(dot(축, cross(시작, 현재)), dot(시작, 현재))
  ```

- **호가 거의 직선으로 보일 때**: 광선이 평면과 거의 평행해서 교점이 불안정합니다. 대신 끈 거리를 호의 길이로 봅니다. 호에서 카메라에 가장 가까운 점이 움직이는 방향 `cross(축, 카메라 방향)`을 화면으로 투영하고, 그 방향으로 호의 반지름만큼 끌면 1라디안 돕니다.

정면이나 축 시점에서는 두 축의 호가 정확히 직선으로 보이므로 두 번째 방식이 꼭 필요합니다.

## Qt 구조

- `MainWindow`(`QMainWindow`)가 메뉴, 툴바, 상태바를 갖고, `MainWidget`을 중앙 위젯으로 둡니다.
- **`QAction` 공유**: 메뉴와 툴바가 같은 액션을 쓰므로 체크 상태와 단축키가 자동으로 맞습니다.
- **`QActionGroup`**: 렌더링 모드 중 하나만 선택되게 합니다.
- **signal/slot**: 액션의 `triggered`를 `MainWidget`의 슬롯에 연결합니다. 슬롯은 값을 바꾸고 `update()`로 다시 그리기를 요청합니다. GL 호출은 `paintGL()`에만 있습니다.
- **위젯 간 연결**: `MainWidget`과 `AxisGizmo`는 서로의 존재를 모르고, `MainWindow::createSidePanel()`에서 시그널과 슬롯만 연결합니다.
- **커스텀 위젯**: `AxisGizmo`는 `paintEvent`로 그리고, `setMouseTracking(true)`로 버튼을 누르지 않아도 마우스를 추적해 호버 표시를 합니다.

## 알려진 한계

- **Wireframe에 대각선이 보입니다.** 큐브 면이 삼각형 2개로 그려지기 때문입니다. 블렌더처럼 사각형 모서리만 보려면 모서리 전용 인덱스를 만들어 `GL_LINES`로 그려야 합니다.
- **선 굵기를 바꾸기 어렵습니다.** Core 프로파일에서 `glLineWidth`의 1보다 큰 값은 드라이버에 따라 동작하지 않습니다.
- **위아래로 넘어갈 수 없습니다.** pitch가 ±90°에서 멈춥니다. 블렌더는 카메라가 머리 위를 넘어갈 수 있는데, 그러려면 뒤집힌 상태에서 좌우 드래그 방향도 함께 바꿔야 합니다.
- **격자가 유한합니다.** ±20 범위라서 많이 줌아웃하면 끝이 보입니다. 블렌더는 멀어질수록 격자가 흐려집니다.
- **시점 전환이 즉시 일어납니다.** 블렌더처럼 부드럽게 이동하지 않습니다.
- **축 위젯의 축 이름은 이 프로그램의 좌표계입니다.** Y가 위쪽이므로 블렌더(Z가 위쪽)와 축 이름이 다릅니다.
- **핸들은 월드 축 기준입니다.** 물체를 돌려도 핸들 축은 그대로입니다. 물체 자신의 축으로 움직이는 로컬 모드는 없습니다.
- **호가 겹치는 점에서는 둘 중 하나가 잡힙니다.** 예를 들어 정면 시점에서 Z 호와 Y 호의 끝이 만나는 곳입니다.
- **선택 표시는 핸들뿐입니다.** 블렌더 같은 주황색 외곽선은 없습니다.
- **선택 중에는 핸들 위에서 시점 회전을 시작할 수 없습니다.** 큐브 중앙은 핸들 위라서 드래그하면 물체가 움직입니다. 빈 곳에서 드래그하세요.
- **이동과 회전 중 취소가 없습니다.** 블렌더는 우클릭이나 `Esc`로 취소할 수 있습니다.
- **기준점이 물체를 벗어날 수 있습니다.** 시점을 옮긴 뒤 회전하면 큐브가 화면 중앙을 중심으로 크게 돕니다. 블렌더의 기본 동작과 같습니다.
- **줌인하면 큐브 안으로 들어갈 수 있습니다.** 기준점이 옮겨진 상태에서는 최소 거리 2로도 카메라가 큐브 내부에 들어갈 수 있고, 이때는 후면 제거 때문에 면이 보이지 않습니다.
